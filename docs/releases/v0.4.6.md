# Faultline v0.4.6

Faultline v0.4.6 keeps the default story narrow: classify the failed log, show
the evidence, and hand off the known fix path. The release favors fewer,
stronger defaults over broad but weak inference.

## What This Release Delivers

- **Default catalog remains focused** — The bundled catalog stays at 173
  playbooks after the v0.4.5 quality pass removed low-signal or overly narrow
  rules from the default bundle.
- **215 accepted real fixtures** — The checked-in real corpus remains at 215
  accepted failures with 100% top-1 and top-3 baseline pass rates.
- **Robustness and playbook refinement** — Several bundled playbooks were
  refined without changing the default release boundary or adding new
  first-run command surfaces.
- **Generated catalog discipline** — Failure catalog docs are generated from
  bundled playbooks and checked by `make docs-check` so documentation drift can
  be caught deterministically.
- **Review noise reduced** — Bundled playbook overlap review remains clean, and
  `make review` passes against the current classified conflict baseline.
- **Specialized paths remain companion or hidden** — Provider-specific,
  maintainer-only, and weakly integrated capabilities stay out of the first-run
  story unless they have deterministic tests, fixture evidence, and release
  verification.

## Release Boundary Status

No change to the default shipping narrative. The default user story remains:

- `analyze`
- `workflow`
- `list`
- `explain`
- `fix`

Local recurrence commands such as `report` and `history` remain companion
surfaces over the local forensic store. They are useful after prior local runs
exist, but they are not the first-run diagnosis path.

Companion and maintainer surfaces remain supported but non-default:
`inspect`, `guard`, `trace`, `replay`, `compare`, `history`, `report`, `packs`,
`batch`, `coverage`, and hidden `fixtures` workflows.
