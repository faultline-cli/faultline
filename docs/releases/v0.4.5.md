# Faultline v0.4.5

Faultline v0.4.5 promotes the Bayesian-inspired reranker to the default,
resolves the long-standing Bayes regression, ships the new `faultline report`
command for local recurring-failure summaries, extracts a dedicated
`internal/coverage` package, removes the hooks system, prunes 20 low-signal
bundled playbooks, adds 54 minimal fixtures to close behavioral coverage gaps,
and expands the real fixture corpus to 215 accepted fixtures.

## What This Release Delivers

- **Bayes promoted to default** — The Bayesian-inspired reranking layer is now
  active by default on all analysis commands (`analyze`, `trace`, `workflow`,
  `inspect`). Users can disable it with `--bayes=false` to fall back to the
  pure deterministic baseline scorer. Promotion criteria: zero regressions
  across all 215 real fixtures (delta 0.000, top-1 1.000, top-3 1.000 in both
  modes). All example snapshots and the release-boundary promotion gate have
  been updated accordingly.
- **Bayes regression resolved** — The known regression on
  `gitlab-gitlab-org-gitlab-runner-6557-s3-64c99cfe7a2f9dfa` (rank 1 → 2
  under `--bayes`) is closed. The fixture was removed during the corpus quality
  pass and the underlying `artifact-upload-failure` playbook now scores
  correctly at rank 1 with or without `--bayes`. `make bayes-check` now reports
  zero regressions across all 215 real fixtures (delta 0.000, top-1 1.000,
  top-3 1.000 in both modes). The known-regression note has been removed from
  `docs/release-boundary.md`.
- **`faultline report` command** — New `faultline report` subcommand reads the
  local Faultline store and groups stored `analyze` runs by failure class,
  showing recurrence counts, last-seen timestamps, and example evidence. Output
  is deterministic markdown table by default or `--json` for
  machine-readable output. Works against the same local SQLite store populated
  by `faultline analyze`.
- **`internal/coverage` package** — Coverage report logic extracted from
  `internal/cli/coverage.go` into a dedicated `internal/coverage` package
  (`report.go` + `report_test.go`). Improves testability and separates
  behavioral evidence accumulation from CLI concerns. 164 test cases in the
  new package.
- **Hooks system removed** — The hooks subsystem (`internal/hooks/hooks.go`,
  `internal/hooks/handlers_test.go`, `internal/playbooks/hooks.go`,
  `internal/model/model_hooks.go`, `internal/output/output_hooks.go`) has been
  deleted. Hooks were an experimental layer that added complexity without a
  clear user-facing surface. Removing it reduces the surface area of the
  codebase by ~2,100 lines and eliminates a dead code path that was not part of
  the release boundary.
- **173 bundled playbooks** (down 20 from v0.4.4's 193). The removed
  playbooks were low-signal or library-specific test patterns with no accepted
  real-corpus fixture support:
  - `remote-cache-miss`, `topology-ownership-mismatch` (build)
  - `step-skipped-unexpectedly`, `workflow-not-triggered` (ci)
  - `link-checker-failure` (network)
  - `topology-failure-clustered` (runtime)
  - `asciidoctor-jbehave-test-failure`, `clock-drift`, `flexget-test-failure`,
    `mdanalysis-test-failure`, `nikola-build-test-failure`,
    `nupic-test-failure`, `openai-gym-test-failure`, `pip-install-test-failure`,
    `python-parser-test-failure`, `random-seed-not-fixed`,
    `readthedocs-build-test-failure`, `sentry-elasticsearch-test-failure`,
    `translate-toolkit-test-failure`, `youtube-dl-test-failure` (test)
- **215 accepted real fixtures** (up 4 from v0.4.4's 211). Four new fixtures
  added: `github-actions-runner-1490` and three Stack Overflow Node.js
  module-resolution / permission questions
  (`stackoverflow-16107789`, `stackoverflow-48910876`, `stackoverflow-50915469`).
- **54 new minimal fixtures** — Behavioral fixture coverage expanded from 25
  to 79 minimal fixtures, closing gaps across `artifact-missing`,
  `base-image-breaking-change`, `build-output-path-mismatch`,
  `cache-corruption`, `cache-miss-non-fatal`, `circleci-resource-class-oom`,
  `cli-flag-changed`, `config-file-missing`, `continue-on-error`,
  `cucumber-step-failure`, `database-migration-timeout`, `dns-enotfound`,
  `empty-deployment-target`, `empty-quality-check`, `encoding-unicode`,
  `entrypoint-misconfigured`, `ffmpeg-avconv-missing`, `git-refspec-mismatch`,
  `gitlab-ci-yaml-invalid`, `gitlab-job-log-limit`, `gitlab-no-runner`,
  `gradle-daemon-timeout`, `ignored-exit-code`, and more.
- **Go test coverage 84.9%** — up from 84.3% in v0.4.4. Coverage gains
  concentrated in `internal/coverage` (new dedicated package), `internal/app`
  (report service tests), and `internal/store` (migration and noop path
  coverage).
- **120 test additions across `cmd/`** — `cmd/root_test.go` adds 104 lines
  covering new command paths; `cmd/release_boundary_test.go` updated to
  reflect the 215-fixture corpus baseline.

## Bayes Regression Closure

The tracked regression was:

> `gitlab-gitlab-org-gitlab-runner-6557-s3-64c99cfe7a2f9dfa`: under `--bayes`,
> `artifact-upload-failure` ranked 2nd instead of 1st.

**Root cause**: The `s3` snippet for this GitLab issue included both
`artifact-upload-failure` signal lines and generic `permission denied` /
`exit code 1` suffixes that slightly elevated a competing candidate's Bayes
posterior. With NativeAny scoring shipped in v0.4.4, the inherited pattern
separation is now handled correctly. The s3 fixture was removed during the
corpus quality pass (it duplicated evidence already covered by the `s1`
fixture without adding unique signal), and verification against its original
log content confirms rank 1 for `artifact-upload-failure` in both baseline
and Bayes modes.

`make bayes-check` now exits successfully with:

```
class: real
fixtures: 215
baseline top_1: 1.000  bayes top_1: 1.000  delta: 0.000
improved: 0  regressed: 0  unchanged: 215
```

The known regression note has been removed from `docs/release-boundary.md`.
Bayes remains opt-in pending explicit promotion review per the gate criteria.

## Release Boundary Status

No change to the default shipping narrative. The default user story remains:

- `analyze`
- `workflow`
- `list`
- `explain`
- `fix`
- `report` *(new — local recurring-failure summary, requires prior `analyze` runs)*

Companion and maintainer surfaces remain supported but non-default:
`inspect`, `guard`, `trace`, `replay`, `compare`, `history`, `packs`, and
hidden `fixtures` workflows.

## Remaining Gaps

- **Corpus mix is still GitHub-heavy.** 104 of 215 accepted fixtures are
  GitHub (48%); future ingestion should continue biasing toward GitLab, Stack
  Exchange, Reddit, and Discourse.
- **Inheritance families are minimal.** Only one bundled inheritance chain
  exists (`node-missing-executable` extends `missing-executable`). The next
  pass should add `python-missing-executable`, `docker-missing-executable`, or
  similar narrowing variants for other common runtime families.
