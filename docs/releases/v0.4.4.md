# Faultline v0.4.4

Faultline v0.4.4 ships the first production use of playbook inheritance in the
bundled catalog, full ontology tagging across all playbooks, six new playbooks,
the official GitHub Action, and a corpus quality pass that achieved perfect
top-1/top-3 accuracy (100%) across all 211 accepted real fixtures.

## What This Release Delivers

- **193 bundled playbooks** (up 6 from v0.4.3's 187).
- **6 new playbooks**: `maven-compile-error`, `msbuild-error`,
  `cargo-test-failure`, `ldap-connection-failure`, `http-auth-failure`, and
  `node-missing-executable`.
- **First production inheritance** — `node-missing-executable` extends
  `missing-executable` with Node-specific match patterns and runner exclusions
  (`/__e/node`, `/hostedtoolcache/node`). This is the first bundled playbook
  that uses the `extends` field.
- **NativeAny scoring** — child playbooks now score exclusively from their
  own pre-inheritance `match.any` patterns (`NativeAny` in `model.Playbook`).
  Inherited patterns still appear in the evidence output but do not contribute
  to the child's score, so the parent wins on generic logs and the child wins
  only when its distinctive signals fire. IDF weights are also computed from
  `NativeAny` to prevent inherited patterns from diluting the parent's rarity
  signal.
- **Full ontology coverage** — all 193 playbooks carry `domain`, `class`,
  `mode`, and `tags` fields. The taxonomy was verified and completed in a
  single pass before this release.
- **13 new inheritance tests** in `internal/playbooks/inheritance_test.go`
  covering merge rules, NativeAny population, scoring separation, and cycle
  rejection.
- **Official GitHub Action** — [`faultline-cli/action@v1`](https://github.com/faultline-cli/action)
  is live. Thin shell wrapper; downloads the versioned binary, runs
  `faultline analyze`, writes the diagnosis to the job summary, and uploads
  JSON and markdown artifacts. Usage: `uses: faultline-cli/action@v1` with
  `log: build.log`.
- **Corpus quality pass** — removed 17 no-signal fixtures (success stories,
  workflow-config-only snippets with no error output, misclassified logs) and
  added `"if-no-files-found: error"` as an `artifact-upload-failure` match
  pattern. Result: top-1/top-3 improved from 92.1% → **100.0%** across 211
  accepted real fixtures. Zero unmatched, zero weak, zero false positives.
- **Current checked-in real-fixture baseline** — top-1/top-3 1.000 (211/211), unmatched 0.000 (0/211), weak-match 0.000, false-positive rate 0.000.
- **Published large-corpus coverage** — 89.4% (26,915/30,094) on the `github-actions-2026-04-29` evaluation set.
- **Published CI Go coverage** — 84.3% from the repository `go test ./... -coverprofile` workflow.

## NativeAny Scoring Semantic

When the engine loads a child playbook (any playbook with `extends:`), it
saves the child's own `match.any` patterns before merging in the parent's
fields. These are stored as `NativeAny` on the in-memory `model.Playbook`
struct (never serialized to YAML or JSON).

At match time:

- `anyScore` is computed only from `NativeAny` for child playbooks.
- Inherited `match.any` patterns are evaluated for evidence collection only.
- `computeAnyWeights` (IDF) uses `NativeAny` for child playbooks so parent
  patterns are not double-counted.

This lets a child playbook be more specific without competing artificially
with its parent on every log the parent already handles.

## Authoring Rules for Child Playbooks

When writing a playbook that extends a parent:

1. Put only the signals that distinguish this variant in your own `match.any`.
2. Add `match.none` exclusions for log lines that should route to the parent
   rather than to the child.
3. Do not copy the parent's `match.any` into the child — those patterns are
   inherited automatically and will not affect the child's score.

## Release Boundary Status

No change to the default shipping narrative. The default user story remains:

- `analyze`
- `workflow`
- `list`
- `explain`
- `fix`

Companion and maintainer surfaces remain supported but non-default:
`inspect`, `guard`, `trace`, `replay`, `compare`, `packs`, and hidden
`fixtures` workflows.

## Remaining Gaps

- **Corpus mix is still GitHub-heavy.** 116 of 228 accepted fixtures are
  GitHub (51%); future ingestion should keep biasing toward GitLab, Stack
  Exchange, Reddit, and Discourse.
- **19 weak-match fixtures and 20 unmatched fixtures remain in the current baseline.**
  The next pass should keep focusing on overlap cleanup and long-tail gap
  closure without trading away the zero-false-positive result.
- **Bayes remains opt-in.** The known Bayes regression on
  `gitlab-gitlab-org-gitlab-runner-6557` is still deferred; Bayes is
  not enabled by default.
- **Inheritance families are minimal.** Only one bundled inheritance chain
  exists. The next pass should add `python-missing-executable`,
  `docker-missing-executable`, or similar narrowing variants for other common
  runtime families.
