# Faultline v0.5.0

Faultline v0.5.0 introduces the Teams authentication and sync layer — the first
milestone toward cross-run coordination and organisational features — and
improves the testability of the interactive login command.

## What This Release Delivers

### `faultline auth` command group

A new `auth` subcommand group provides interactive and non-interactive
authentication against the Faultline Teams API.

- **`faultline auth login`** — Authenticates via email/password (prompts
  interactively, or accepts `--email` / `--team` flags). Stores a persistent
  `ft_…` API token at `~/.config/faultline/credentials` (0600). Respects
  `$FAULTLINE_API_URL` to target staging or on-premise deployments.
- **`faultline auth logout`** — Removes stored credentials. Idempotent; safe to
  call when not logged in.
- **`faultline auth status`** — Verifies the stored token against the Teams API
  and prints the authenticated identity and team. Prints re-authentication
  guidance when the token is invalid or expired rather than returning an error.
- **`faultline auth token set <token>`** — Stores an `ft_…` token directly;
  designed for CI environments where interactive login is not possible.
  `$FAULTLINE_TOKEN` is also accepted as an alternative to on-disk storage.

### `internal/teams` package

New package encapsulating Teams API connectivity and credential persistence:

- **`client.go`** — Minimal HTTP client for the Teams API. Implements
  `Login` (two-step: Better Auth sign-in then token creation), `VerifyToken`
  (GET /v1/auth/me), and `Sync` (POST /v1/sync/artifacts). The HTTP client has
  a 30-second timeout and cookie-jar support. Error response bodies are capped
  at 4 KiB via `io.LimitReader` (OWASP A10 — Mishandling of Exceptional
  Conditions).
- **`config.go`** — Credentials persistence following the XDG Base Directory
  Specification. Credentials file uses 0600 permissions; the config directory
  uses 0700.

### `faultline sync`

`faultline sync` pushes the first-class artifact from
`faultline analyze --json` to Faultline Teams. It accepts a file path or stdin,
requires a project ID through `--project` or `$FAULTLINE_PROJECT`, and uses
stored credentials or `$FAULTLINE_TOKEN`.

The command remains a supported companion surface, not part of the default
local-first diagnosis story.

### Testability improvement — interactive login

`newAuthLoginCommand` previously hardcoded `os.Stdin` and
`os.Stdin.Fd()` directly, making the `RunE` body untestable (18.4%
coverage). Refactored to:

- Use `cmd.InOrStdin()` for all input so tests can inject via `cmd.SetIn()`.
- Extract `readPassword(r io.Reader, fallback *bufio.Scanner)` — uses
  `term.ReadPassword` when `r` is a terminal (`*os.File`), and falls back to
  the scanner for non-TTY readers (pipes, test buffers). This preserves the
  interactive UX for real users while enabling unit-test coverage.

Coverage of `newAuthLoginCommand` improved from 18.4% to 94.9%.

### Release boundary

`auth`, `sync`, and their subcommands are registered in `CommandSurfaces` as
`SurfaceCompanion / MaturitySupported`, consistent with `report`.

## Test Coverage

Test coverage expanded across `internal/teams`, `internal/cli`, `internal/app`,
and `internal/engine`:

**`internal/teams/config_test.go`** — credentials round-trip,
file/directory permissions (0600/0700), XDG path resolution, fallback to
`~/.config` when `XDG_CONFIG_HOME` is unset, missing-file nil-return,
idempotent clear, corrupt-JSON error, and unreadable-file error.

**`internal/teams/client_test.go`** — `Login` success and all failure paths
(401, 400, 5xx, token creation failure, large body truncation, malformed
sign-in response, malformed token response, network error); `VerifyToken`
(success, invalid token, server error, empty team slug, malformed response,
network error); `Sync` (success with header/body assertions, status-error
subtests, large body truncation, malformed response, network error); HTTP
client timeout assertion.

**`internal/cli/cmd_auth_test.go`** — `logout` (clear, idempotent); `status`
(not logged in, valid token via mock server, expired token, empty token);
`token set` (prefix validation, storage, `--api-url` flag,
`$FAULTLINE_API_URL` env fallback, default production URL); `login` (all
flags, prompted inputs, empty-input validation, password EOF, authentication
failure, save-credentials failure when config dir is read-only); command
structure assertions.

**`internal/app/sync_test.go` and `internal/cli/cmd_sync_test.go`** — sync
request construction, environment and stored credential behavior, artifact
shape validation, oversized input rejection, and command wiring.

Coverage summary: `internal/teams` is 87%, `internal/cli` is 82.2%, and the
overall project coverage run reports 88.8%.

v0.5.0 should be validated with:

- `make test`
- `make fixture-check`
- `make bayes-check`
- `make review`
- `make docs-check`
- `make cli-smoke`
- `make release-check VERSION=v0.5.0`

## Release Boundary Status

The default user story is:

- `analyze`
- `batch`
- `workflow`
- `list`
- `explain`
- `fix`
- `inspect`

`report`, `auth`, and `sync` are supported companions. All `fixtures *` commands remain
hidden maintainer utilities.
